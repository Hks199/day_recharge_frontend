# Landing page design

The public landing page follows the visual reference supplied by the user: https://dayrecharge.com/ (reviewed October 10, 2026). `home.css` scopes the home-specific design: a tall navy hero, cyan/teal headline, pill actions, floating artwork cards, a compact six-service strip, six feature cards beside an introduction, three role cards, a pink-to-cyan call-to-action, and the shared dark footer. The header follows the reference's Home/About/Contact/Terms navigation. Content and navigation remain connected to this project's supported workflows.

`public/images/digital-services.png` is the reference site's illustration, downloaded from https://dayrecharge.com/img/banner.png and served locally. Service icons (`recharge.png`, `api.png`, `dth.png`, `BBPS_Logo.png`) were also downloaded from its public `/img/` assets and are served locally. Tenant branding and support details continue to come from the existing branding provider. Home actions use `/register`, `/login`, and `/contactus`. The backend has no public signup or app-download endpoint; registration opens the access-request page and the green hero action opens support. Capability labels and supported role descriptions replace unverified usage, earnings, success-rate claims, and extra business roles. Wallet transfers refer to the supported internal wallet workflow.

Responsive browser checks cover 320, 360, 390, 640, 768, 900, 1024, and 1440 pixels, plus mobile navigation, the Terms page, service links, local calls to action, local asset loading, and horizontal scroll prevention. The decorative hero artwork hides below the desktop breakpoint, as in the reference. The mobile capability strip wraps to prevent the reference's horizontal overflow. The previous extra FAQ and steps sections were removed to match the requested home-page composition; existing `#services`, `#how-it-works`, and `#contact` anchors remain valid.

`Footer.tsx` and `footer.css` reproduce the reference's four-column layout, support panel, gradient action, and copyright strip with internal navigation. The default header and footer show the original-color logo served locally from `public/images/day-recharge-logo.jpg`, sourced from the reference site's branding image. Service and access links use `/login`; About and Contact use local section anchors. Support details come from the branding provider. Unconfigured social links and external developer links are omitted.

Terms and Privacy links open the local `/terms` and `/privacy` pages. No API calls, asset requests, or redirects to the reference site are configured; the existing application API remains in use. Browser checks verified local logo loading, internal links, dialogs, and no reference-site requests. Footer layouts were checked at 320, 390, 768, 1024, and 1440 pixels.

The `/aboutus` page follows the supplied About Us reference, with a pink-to-dark banner, two-column introduction, and four feature tiles. Copy describes this application's supported roles and services. `MarketingHeader.tsx`, `Brand.tsx`, and `Footer.tsx` are shared by both public pages, and About links use the local route. About page browser coverage checks direct visits, header/footer navigation, mobile menu, local assets and links, and overflow at 320, 390, 768, and 1440 pixels.

The `/contactus` page reproduces the reference's gradient banner, company information card, and message form. Header and footer Contact links use this local route. On the platform hostname, the contact card uses the reference's public address, phone, and email; configured support contacts take precedence. Tenant hostnames use their own configured support contacts and do not fall back to the reference company's details.

The backend has no unauthenticated public contact submission endpoint. A validated message opens a `mailto:` draft for the visitor to review and send in their own email application; the page explains this before submission and does not claim the message was delivered. Nothing is posted to the reference site. Browser checks cover required fields, draft contents, internal navigation, local-only requests, and 320, 390, 768, and 1440 pixel layouts.

The `/login` page follows the supplied login reference: a 45/55 split, navy gradient introduction, locally served transparent logo, feature rows, pale background, rounded white card, gradient sign-in button, and a centered card on mobile. `public/images/day-recharge-login-logo.png` was downloaded from the reference's branding image. Email/password authentication, validation, password visibility, session notices, and role-based destinations remain connected to this application's API. Unsupported remember-me persistence, app downloads, and unverified usage figures are replaced with supported local navigation and business information. Browser coverage includes all four role destinations and widths from 320 to 1440 pixels.

The login page's Register now link opens `/register`. Following the user's registration-page request, this page shares `AuthStory.tsx` with login and reproduces the reference's wider card, two-column desktop fields, mobile field stack, icons, policy links, and gradient action. The backend's auth routes were checked and have no public registration endpoint. The form therefore requests administrator-created access through an email draft; it clearly explains this before submission and never claims an account was created. It validates name, Indian mobile number, email, and a preferred Retailer/Distributor role. It does not collect unused passwords, introduce the reference's unsupported API User role, or post to the reference site. Terms and Privacy open the local `/terms` and `/privacy` pages. Tenant support emails take precedence, and unconfigured tenant support disables the request action. Browser tests cover responsive layouts, login/register navigation, policy dialog, validation, draft contents, and the absence of registration API calls.
`Terms.tsx` and `terms.css` recreate the supplied legal-page layout: full-width gradient banner, dated subtitle, centered rounded white article, five numbered sections, and the shared header/footer. The supplied reference `/term` returns HTTP 404; `/terms` is its working page. Both local URLs are supported, with `/term` redirecting locally to `/terms`. Body wording is adapted from the reference, with supported wallet transfers replacing external remittance claims and the configured brand name used in the text. The update date is fixed to 10 October 2026, rather than changing automatically on every visit. Header, footer, and registration Terms links navigate to the page. Browser checks cover both URLs, all five sections, mobile navigation, local-only requests, and widths of 320, 390, 768, 1024, and 1440 pixels.
`Privacy.tsx` reproduces the supplied `/privacy` reference using the shared legal-page styles in `terms.css`: gradient banner, fixed update date, centered white article, five numbered sections, and shared branding, navigation, and footer. The body wording is adapted from the reference. Security and cookie descriptions reflect the inspected backend (password hashing, protected refresh credentials, and scoped access) rather than asserting unverified IP whitelisting or full session restoration. The Contact page link navigates locally to `/contactus`. Footer company/legal links and registration Privacy links now open `/privacy`, replacing the former placeholder dialogs. Browser coverage checks the five sections, document title, fixed date, local navigation, no reference-site requests, and no horizontal overflow at 320, 390, 768, 1024, and 1440 pixels.
The public navbar is now identical on Home, About, Contact, Terms, and Privacy. `MarketingHeader.tsx` renders one shared Home/About/Contact/Terms link set, with Login and Get Started actions; only the active-page highlight changes. Get Started always targets `/register`. `marketing-header.css` keeps header height, logo size, spacing, and mobile actions consistent across routes. The mobile menu includes both account actions. A navigation regression test follows the links on mobile and desktop and verifies stable labels, header size, destinations, menu closing, and no horizontal overflow.
